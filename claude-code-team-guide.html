Settings & Security

Permissions in .claude/settings.json control what Claude Code can and cannot do.

12 Allow Rules

Safe, scoped commands:

npm test npm run lint npm run build npm run format npx tsc npx prettier git status git log git diff git add git commit git branch

7 Deny Rules

Destructive commands blocked:

rm -rf git push -f git reset --hard DROP TABLE node * cat * find *

Key decisions: Removed dangerous wildcard permissions (node *, cat *, find *). The .env.local file is protected from edits. Pre-commit hook handles formatting so there are no fragile hooks to break.

The Rules

Path-scoped rules load automatically when editing specific files.

.claude/rules/api-security.md

Only loads when editing app/api/**/*.ts files

  • IP extraction — safe headers for rate-limiting behind proxies
  • Structured logging — consistent error tracking format
  • Error responses — never leak stack traces to clients
  • Rate limiting — token bucket with configurable limits

Design choice: Only 1 path-scoped rule was created. Everything else lives in CLAUDE.md as the single source of truth. Rules are for context that should only appear when relevant files are open.

What's NOT Included (and Why)

Intentionally cut to keep the system lean. Each omission has a rationale.

animation-specialist 3 animation files in the entire project — too niche for a dedicated agent
performance-optimizer Monthly task at most — use the bundle analyzer directly when needed
interview-prep Occasional use — just ask Claude directly, no agent prompt needed
competitive-intel Quarterly at best — use WebSearch tool when the need arises
hooks Broken on Windows, redundant with pre-commit — more trouble than value
